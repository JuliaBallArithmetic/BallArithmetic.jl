API - Core Types

Core ball arithmetic types and basic operations.

The Module

BallArithmetic.BallArithmetic — Module
BallArithmetic

Tools for rigorous linear algebra with floating-point balls. The package builds on Ball numbers—midpoint/radius pairs that track rounding error—to provide array, matrix, and vector types with propagated uncertainty. High-level routines such as norm bounds, eigenvalue certification, and singular value enclosures are exposed via this module after it has been loaded.

Most functionality is available through exported symbols documented in the respective source files. Loading the module also enables auxiliary utilities such as rigorous rounding macros and promotion rules that let Ball values interact seamlessly with base Julia numeric types.

Ball Type

BallArithmetic.Ball — Type
Ball{T, CT}

Closed floating-point ball with midpoint type CT and radius type T. Each value represents the set { c + δ : |δ| ≤ r } where c::CT is the stored midpoint and r::T ≥ 0 is the radius. Both real and complex midpoints are supported as long as the radius is expressed in the underlying real field. The type behaves as a number and participates in arithmetic with rigorous outward rounding.

BallArithmetic.ball_hull — Function
ball_hull(a::Ball, b::Ball)

A ball containing both a and b.

For real midpoints the result encloses [min(inf(a), inf(b)), max(sup(a), sup(b))], the interval hull of the two sets; the enclosure is the one _ball_from_bounds states.

For complex midpoints the midpoint of the result is that of a or that of b, whichever gives the smaller radius, and the radius is max(rad(x), add_up(dist_up(mid(a), mid(b)), rad(y))) with x the argument whose midpoint was kept and y the other one. The disc of x is contained because the radius is at least rad(x), and the disc of y because every one of its points is within |mid(a) − mid(b)| + rad(y) of the midpoint that was kept. The result is not the smallest enclosing disc, whose centre lies between the two midpoints.

Note that dist_up bounds the distance through abs_up(::Complex), which squares the components of the difference, so the radius is Inf once a component passes about sqrt(floatmax(T)).

BallArithmetic.in0 — Function
in0(B₁::Ball, B₂::Ball)

Return true when B₁ is contained in the interior of B₂, which for balls is |mid(B₁) − mid(B₂)| + rad(B₁) < rad(B₂). The left-hand side is bounded above, the distance of the centres by dist_up and the sum by add_up, and compared against the stored radius, which is exact, so a true answer is a proof of the containment. (The modulus of a complex difference is not obtained from abs under an upward rounding mode: abs is hypot, which does not honour it, and the difference itself rounds a negative component toward zero.)

This is the predicate Rump writes in0 and defines in footnote 19 of

S. M. Rump, Verification methods: rigorous results using floating-point arithmetic, Acta Numerica 19 (2010) 287-449, doi 10.1017/S096249291000005X,

as "checks X ⊂ int(Y) componentwise". Every self-mapping test in the Krawczyk-Moore-Rump line needs the interior, not the closure: a fixed point on the boundary satisfies X ⊆ Y without giving the contraction the argument rests on, so in, which is not strict, is not a substitute.

BallArithmetic._ball_from_bounds — Function
_ball_from_bounds(lo, hi)

The ball enclosing the interval [lo, hi], for floating-point endpoints with lo ≤ hi. inv, sqrt and abs of a real ball, and ball_hull and intersect_ball, all build their result here.

Writing B for the result, what is guaranteed is that in exact arithmetic

B.c − B.r ≤ lo    and    B.c + B.r ≥ hi,

so that [lo, hi] ⊆ [B.c − B.r, B.c + B.r], together with B.r ≥ 0. Each of the two inequalities follows from one directed subtraction on its own: the radius is at least sub_up(B.c, lo) ≥ B.c − lo, which gives the first, and at least sub_up(hi, B.c) ≥ hi − B.c, which gives the second, so neither appeals to the direction in which the midpoint was rounded. A radius measured from one end alone, or from the half-width, reaches the other end only when the midpoint lies on the far side of (lo + hi)/2, and that is where issue #73 came from: the ball_hull of v0.3.0 rounded the midpoint to nearest and took the radius to be the half-width rounded up, so on ball_hull(Ball(-1.0, 0.5), Ball(-0.6, 0.75)) the upper end of the result fell one unit in the last place below the upper end of its second argument. The version that preceded this one rounded the midpoint up and measured the radius from lo, which encloses, but only because of the direction of that rounding.

The midpoint is lo + (hi − lo)/2 rounded up where hi − lo is representable, and lo/2 + hi/2 rounded up where it is not, so an interval wider than floatmax(T) still has a finite midpoint. Both forms give B.c ≥ (lo + hi)/2 exactly, which is what keeps the radius near the half-width rather than near the full width; the enclosure above does not depend on it.

An endpoint that is infinite returns Ball(zero(T), T(Inf)), the whole line being the only enclosure of an unbounded interval that a ball with a finite midpoint admits. Endpoints out of order, and an endpoint that is NaN, raise an ArgumentError: neither describes a set to enclose.

source
BallArithmetic.BallMatrix — Type
BallMatrix{T, NT, BT, CM, RM}

Alias for the two-dimensional BallArray used to represent matrices with rigorous error control. The type parameters mirror those of BallArray and describe the base floating-point type T, the element type NT, the Ball container BT, and the concrete matrix types used for the midpoints (CM) and radii (RM).

Users typically construct instances through the BallMatrix constructors below rather than specifying these parameters explicitly.

What set of matrices a ball matrix is

A ball matrix is the set of the matrices whose stored entries lie in the stored balls: an entry with midpoint m and radius r ranges over |x − m| ≤ r, and an entry that is not stored has no tolerance of its own. The storage types CM and RM therefore say what the set is, and the routines dispatch on them.

  • Midpoint and radius stored as plain matrices: every entry is stored, and the set is the matrices X with |X − M| ≤ R entrywise. With positive radii it is an open set of matrices, whatever M is: it contains matrices that are not Hermitian, not symmetric, not triangular. Enclosures of its eigenvalues are discs of the complex plane.
  • Midpoint and radius stored as Diagonal, or as triangular: the entries outside the structure are zero and are not stored, so every matrix of the set is diagonal, or triangular.
  • Midpoint stored as Hermitian (or real Symmetric) and radius stored as Symmetric: one triangle is stored, with one tolerance for each pair {i, j}, and the other triangle is determined by it. Every matrix of the set is Hermitian: it is the Hermitian matrices X with |X − M| ≤ R, a HermitianBallMatrix. Enclosures of its eigenvalues are real intervals, and the statements of the routines are for these Hermitian matrices.
  • Midpoint stored as Hermitian and radius stored as a plain matrix: every entry has its own tolerance, so the perturbation has no structure and the set is the full entrywise ball around a Hermitian midpoint. The enclosures are discs; what the storage of the midpoint changes is the approximation that is certified, which is that of a Hermitian matrix.

A routine that writes a structured ball matrix out as a dense one computes on a larger set for the Hermitian kind (the two triangles then vary independently) and on the same set for the diagonal and triangular kinds; the statement it returns is the one of the kind it was given.

Sums, differences and real multiples of Hermitian ball matrices are Hermitian ball matrices; products are not, and are returned with plain storage.

BallArithmetic._zero_radius — Function
_zero_radius(A, ::Type{T})

Return an all-zero, T-valued array laid out like A. Structured and sparse midpoints keep their storage type, so BallMatrix(Diagonal(...)) gets a Diagonal radius rather than a dense one — for a sparse midpoint the dense fallback costs orders of magnitude more memory than the midpoints themselves.

This is sound because every entry a structured type stores implicitly is an exact zero (or, for the unit triangular types, an exact one), so the corresponding radius is exactly zero and needs no storage.

fill!(similar(A, T), zero(T)) is used rather than zero(A), which would keep a complex element type, or zero(similar(A, T)), which reads the undefined references similar leaves behind for BigFloat.

For Adjoint, Transpose, SubArray and ranges similar already yields a plain dense array, matching the previous behaviour.

BallArithmetic._check_axes — Function
_check_axes(c, r)

Reject midpoint and radius containers that do not line up. Mismatched shapes used to be accepted silently: the resulting object reported size(c) while indexing or norm bounds later failed with a confusing BoundsError or DimensionMismatch far from the construction site.

Comparing axes rather than size keeps offset-indexed arrays working. The check is O(1), so it costs nothing on the hot paths.

source

The radii are not checked on construction, since the scan would cost more than the arithmetic it guards; the axes of the midpoint and radius containers are, that test being O(1). Radii of external provenance go through one of the two predicates below first.

BallArithmetic.isvalid_enclosure — Function
isvalid_enclosure(A::BallArray) -> Bool

Report whether every radius of A is a genuine enclosure radius, that is non-negative and not NaN. A negative or NaN radius describes no set at all, so an array failing this test carries no rigorous meaning.

Validating the radii is the caller's responsibility. The package deliberately does not check them on construction: the radii it produces internally are non-negative by construction (accumulated under RoundUp from non-negative quantities), and scanning every entry would cost up to 76% of a BallMatrix addition at n = 100. When radii come from outside — read from a file, supplied by a user, converted from another package — call this (or check_enclosure) yourself before relying on the enclosure.

The axes of c and r are checked on construction, since that test is O(1).

The Base interface of the ball types

What follows is the arithmetic and the array interface that Ball, BallArray, BallMatrix and BallVector add to Base. Every operation returns an enclosure: the midpoint is the floating-point result and the radius carries the radii of the operands together with a bound on the rounding of the midpoint, accumulated with the directed operations of Arithmetic and Rounding. The comparisons are the exception, and the one place where a result is not a proof of anything about the enclosed sets: they compare midpoints, so that balls can be sorted, and a rigorous "certainly less than" is sup(a) < inf(b).

Base.inv — Method
inv(x::Ball{T, Complex{T}})

Return the multiplicative inverse of a complex ball. The method throws an ArgumentError when the ball is not proved to exclude zero. The image of the disc B(m, r) under 1/z is the disc B(conj(m)/D, r/D) with D = |m|² − r². D is bracketed by D_lo ≤ D ≤ D_hi with directed operations and D_lo > 0 is required; the centre is computed with D_lo, and the radius is r/D_lo plus the distance |m|(1/D_lo − 1/D_hi) between that centre and the exact one, plus the rounding of its two divisions.

Whether a Result Is Proved

Every result type whose computation can fail to prove what it claims carries one boolean field, certified. iscertified reads it whatever the type, and reads it as well under the names the same flag had in version 0.3.0, success, verified, is_regular and precomputation_success, which still resolve with a deprecation warning.

BallArithmetic.iscertified — Function
iscertified(result) -> Bool

Whether result proves what it computes: true when the verification behind it succeeded, so that the statement in the docstring of typeof(result) holds for every matrix and every vector of the input balls, and false when some step of that verification did not apply, in which case the enclosures carried by result prove nothing and usually have infinite radii.

This is the supported way to ask the question. The field it reads is called certified in version 0.4; in 0.3.0 it was called success on the verified decompositions, on the generalised eigenvalue results and on most of the linear system solvers, verified on KrawczykResult, NKEigenpairResult, Oishi2023Result, RumpOishi2024Result and VerifiedLinearSystemResult, is_regular on RegularityResult and precomputation_success on SylvesterResolventResult. Code that calls iscertified reads the flag in either version.

A type that carries no such flag raises an ArgumentError naming it, in place of returning false: a false would read as "not proved", which is a claim about a computation that the type never made. The flags that mean something else, and so are not read here, are converged of the iterative methods and of the refinements, which is about an iteration reaching a tolerance; spectrum_covered of VerifyEigAllResult, which asserts in addition that the union of the discs holds the whole spectrum; empty of IterativeResult and of ShavingResult; and success of PreconditionerResult, whose preconditioner is an approximate inverse.

Example

B = randn(100, 100); A = B' * B + I
iscertified(verified_cholesky(Float64, A))     # true: A is positive definite
iscertified(verified_cholesky(Float64, [1.0 2.0; 2.0 1.0]))     # false: it is not

BallArithmetic.collatz_upper_bound_L2_opnorm — Function
collatz_upper_bound_L2_opnorm(A::BallMatrix; iterates = 5)

A rigorous upper bound on the spectral norm of every matrix in the ball A, by Collatz's inclusion applied to |A|ᵀ|A|.

Reference

S. M. Rump, Verified bounds for singular values, in particular for the spectral norm of a matrix and its inverse, BIT Numer. Math. 51 (2011) 367-384, doi 10.1007/s10543-010-0294-0, Section 3: for real or complex A,

‖A‖₂ ≤ ‖ |A| ‖₂                                                      (3.2)

and, for nonnegative B, since ‖B‖₂² = ρ(BᵀB) and BᵀB is nonnegative, "Collatz' Theorem in Perron-Frobenius Theory yields"

‖B‖₂² ≤ max_i (Bᵀ(Bx))_i / x_i      for every positive vector x.     (3.3)

"Few power set iterations starting with the vector of 1's" give the vector. Here B is upper_abs(A), an entrywise upper bound of |M| for every M in the ball, which is enough because ρ is monotone on nonnegative matrices.

iterates is the number of power iterations used to choose x; any value, including zero, gives a valid bound (with zero it is √‖BᵀB‖_∞). The result is Inf when the quotient is not finite.

source
BallArithmetic.svd_bound_L2_opnorm — Function
svd_bound_L2_opnorm(A::BallMatrix{T})

A rigorous upper bound of ‖A‖₂ over the matrices of the ball A, the largest singular value of the enclosure rigorous_svd returns, rounded up. Inf is returned when that enclosure does not certify, and upper_bound_L2_opnorm then keeps its cheaper bounds.

The cost is the O(n³) of the verified factorisation, against O(k n²) for collatz_upper_bound_L2_opnorm and O(n²) for √(‖A‖₁‖A‖_∞), and it is the tightest of the three for a general matrix, since the other two bound the spectral norm through quantities that do not attain it. How much tighter is a property of the matrix and is not reported here: this docstring carried a table of overestimation percentages, "~0%" for the singular value bound against "0-500%" for Collatz with figures per matrix type, which nothing in the package measures; it was removed on 2026-11-08.

Example

fast_bound = upper_bound_L2_opnorm(A)  # Looser bound, faster

See also: upper_bound_L2_opnorm, collatz_upper_bound_L2_opnorm, rigorous_svd

svd_bound_L2_opnorm_inverse(A::BallMatrix)

BallArithmetic.rump_oishi_2024_triangular_bound — Function
rump_oishi_2024_triangular_bound(T::BallMatrix, k::Int) -> upper bound of ‖T⁻¹‖₂

Theorem 1.3 of Rump and Oishi for an upper triangular T, split as T = [A B; 0 D] with A of order k, and D = D_d + D_f into its diagonal and the rest. The lower left block is zero, so the theorem reads: if ‖D_d⁻¹ D_f‖₂ < 1, then T is invertible and

‖T⁻¹‖₂ ≤ max{ ‖A⁻¹‖₂, ‖D_d⁻¹‖₂ / (1 − ‖D_d⁻¹ D_f‖₂) } · ψ(‖A⁻¹B‖₂),

with ψ(μ) the norm of [I −N; 0 I] for ‖N‖₂ = μ (Lemma 1.2, psi_schur_factor). The bound holds for every matrix of the ball T. Inf is returned where the hypothesis is not established or a diagonal entry of D may vanish. For k equal to the order the result is svd_bound_L2_opnorm_inverse of T.

How each quantity is bounded: ‖A⁻¹‖₂ by svd_bound_L2_opnorm_inverse; A⁻¹B is enclosed by backward_substitution and its norm, like that of D_d⁻¹ D_f (formed by ball divisions), bounded by collatz_upper_bound_L2_opnorm; ‖D_d⁻¹‖₂ is the largest 1/mig(d_ii); the final operations are rounded upwards.

The note states the theorem for real matrices. Complex triangular matrices are accepted here: the block factorisation, the Neumann series and Lemma 1.2 use only the norm.

Reference

S. M. Rump and S. Oishi, A note on Oishi's lower bound for the smallest singular value of linearized Galerkin equations, Japan J. Indust. Appl. Math. 41(2) (2024), 1097-1104, doi 10.1007/s13160-024-00645-7 ([8]), Lemma 1.2 and Theorem 1.3.

BallArithmetic.upper_abs — Function
upper_abs(A)

Entrywise upper bound of |C| + R for a ball matrix with midpoint C and radius R, so that |X| ≤ upper_abs(A) entrywise for every X in the ball; for a plain matrix, of |A|.

Every norm bound below goes through this matrix: the spectral, Frobenius, ℓ¹ and ℓ^∞ norms are monotone in the moduli of the entries (Higham, Accuracy and Stability of Numerical Algorithms, 2nd ed., Lemma 6.6, for the spectral norm), so a bound on the norm of |C| + R bounds the norm of every matrix in the ball, and it is never larger than the norm of C plus the norm of R.

For Float32 and Float64 the moduli are formed with abs_up, as √(re² + im²) rounded upward operation by operation, because the complex abs is hypot, which is not correctly rounded and so is not a bound under RoundUp.

The L2 Operator Norm: What Each Bound Costs

The package offers four routes to an upper bound of ‖A‖₂, and they differ in cost:

MethodComplexityWhat it bounds the norm by
svd_bound_L2_opnormO(n³)the largest singular value of a verified factorisation, rounded up
collatz_upper_bound_L2_opnormO(k·n²)the Collatz-Wielandt bound after k iterations on |A|ᵀ|A|
sqrt(‖·‖₁·‖·‖∞)O(n²)‖A‖₂ ≤ √(‖A‖₁·‖A‖_∞)
upper_bound_L2_opnormO(k·n²)the least of the cheap bounds, and of the singular value bound when asked for it

The first is the tightest for a general matrix, since the other three bound the spectral norm through quantities that do not attain it. How much tighter is a property of the matrix, and this page carried a table of overestimation percentages per matrix type, together with a block of benchmark figures, which nothing in the package measures; both were removed on 2026-11-08 rather than left for a reader to rely on. The same claims were in the docstring of svd_bound_L2_opnorm and went with them.

BallArithmetic.oishi_2023_sigma_min_bound — Function
oishi_2023_sigma_min_bound(G::BallMatrix{T}, m::Int) where {T}

Compute a rigorous lower bound on the minimum singular value of G using the Schur complement method from Oishi (2023).

Arguments

  • G::BallMatrix: The matrix to analyze
  • m::Int: Block size for the partition (A is m×m)

Method (Theorem 1 from Oishi 2023)

Partition G as:

G = [A  B]
    [C  D]

where A ∈ Mm, B ∈ M{m,n-m}, C ∈ M{n-m,m}, D ∈ M{n-m,n-m}.

Let Dd and Df be the diagonal and off-diagonal parts of D.

If the following conditions hold:

  1. ‖A⁻¹B‖₂ < 1
  2. ‖CA⁻¹‖₂ < 1
  3. ‖Dd⁻¹(Df - CA⁻¹B)‖₂ < 1

Then G is invertible and:

‖G⁻¹‖₂ ≤ max{‖A⁻¹‖₂, ‖D_d⁻¹‖₂/(1 - ‖D_d⁻¹(D_f - CA⁻¹B)‖₂)}
         / ((1 - ‖A⁻¹B‖₂)(1 - ‖CA⁻¹‖₂))

Since σmin(G) = 1/‖G⁻¹‖₂, this gives a lower bound on σmin.

Returns

Oishi2023Result containing the bounds and verification status.

Reference

S. Oishi, Lower bounds for the smallest singular values of generalized asymptotic diagonal dominant matrices, Japan J. Indust. Appl. Math. 40 (2023), 1569-1585, doi 10.1007/s13160-023-00596-5 ([9]), Theorem 1.

Rump-Oishi 2024 Improved Schur Complement Bounds

Improved bounds from Rump & Oishi (2024), "A Note on Oishi's Lower Bound for the Smallest Singular Value of Linearized Galerkin Equations".

Key Improvements over Oishi 2023

  1. Removes conditions 1 & 2: No longer requires ‖A⁻¹B‖ < 1 and ‖CA⁻¹‖ < 1. Only condition 3 (‖Dd⁻¹(Df - CA⁻¹B)‖ < 1) is needed.

  2. Uses exact ψ(N) formula: Instead of 1/(1-‖N‖), uses ψ(μ) = √(1 + 2αμ√(1-α²) + α²μ²) which is tighter and works for any μ ≥ 0.

  3. Fast γ bound (optional): Uses π(N) = √(‖N‖₁·‖N‖∞) to quickly check if the method will succeed, avoiding expensive matrix products and reducing complexity from O((n-m)²m) to O((n-m)m²).

Example

using BallArithmetic, LinearAlgebra

# Create a diagonally dominant matrix (Example 3 from paper)
k, n = 0.9, 50
G_mid = [i == j ? Float64(i) : k^abs(i-j) for i in 1:n, j in 1:n]
G = BallMatrix(G_mid, zeros(n, n))

# Compute bounds with optimal block size
best_m, result = rump_oishi_2024_optimal_block_size(G; max_m=30)

if result.certified
    println("σ_min(G) ≥ ", result.sigma_min_lower)
    println("‖G⁻¹‖ ≤ ", result.G_inv_upper)
    println("Optimal block size: m = ", best_m)
    println("Used fast γ bound: ", result.used_fast_gamma)
end

BallArithmetic.psi_schur_factor — Function
psi_schur_factor(μ::T) where {T}

Compute ψ(μ) from Lemma 1.2 of [8].

For a block triangular matrix H = [I, -N; 0, I] with ‖N‖ = μ, this computes the exact value of ‖H‖ = ‖H⁻¹‖.

The paper's formula (5) is

α = √(½(1 + 1/√(1 + 4/μ²))),      ψ(μ) = √(1 + 2αμ√(1-α²) + α²μ²).

It is evaluated here in the equal form ψ(μ) = (μ + √(μ² + 4))/2: β = α² solves β² − β + 1/(4 + μ²) = 0 (the proof of Lemma 1.2), so α√(1-α²) = 1/√(4 + μ²) and, with t = μ/√(μ² + 4), β = (1 + t)/2, whence ψ² = 1 + 2t + μ²(1 + t)/2 = ((μ + √(μ² + 4))/2)². Formula (5) is the maximum over α of the quantity (6), so an α carrying a rounding error gives a value below ψ; the closed form has no such step.

This replaces the weaker bound 1/(1-μ) used in Oishi 2023, and works for any μ ≥ 0. By (10) of the paper an upper bound of ‖N‖ may be passed for μ.

Returns

An upper bound of ψ(μ).

source
BallArithmetic.psi_squared — Function
psi_squared(μ)

An upper bound of ψ(μ)² = 1 + μ²/2 + (μ/2)√(μ² + 4), rounded up.

For S(X) = [I X; 0 I] and μ = ‖X‖₂, ‖S(X)‖₂ = ‖S(X)⁻¹‖₂ = ψ(μ), so ψ(μ)² is the condition number of S(X) in the spectral norm: with the singular value decomposition of X the matrix S(X)*S(X) splits into blocks [1 σ; σ 1 + σ²], whose largest eigenvalue is 1 + σ²/2 + (σ/2)√(σ² + 4), increasing in σ; and S(X)⁻¹ = S(−X). Being increasing, the function may be evaluated at an upper bound of ‖X‖₂.
